## Decisions made
(one line each; also recorded in `docs/DECISIONS.md`)
- Review flow (approved): client-side only; API returns `review_queue`, stores nothing.
- Primary LLM (D-028, supersedes D-001): `gemini-3.5-flash-lite`, AI Studio free tier (`gemini-2.0-flash` retired; `gemini-3.8-flash` free = 20 requests/day).
- Fallback LLM (D-029, supersedes D-002): `qwen/qwen3.8-27b:free` via OpenRouter, $0, different company (free: 20/min, 50/day).
- Judge LLM (D-030, supersedes D-003): `gemini-3.1-flash-lite`, a different model from the localizer (Pro free limit = 0; `gemini-2.5-pro` 404 for new keys).
- Cost (D-031): exact-id prices with sources; every cost log line has `cost_usd` (actual, 0 on free tiers via `LLM_BILLING=free` or a `:free` id) and `list_cost_usd` (paid list price). `raw_v2.txt` names its JSON key (D-032). Free-tier data use stated in `docs/AI_APPROACH.md` (D-033).
- Confidence: 0.35×term + 0.25×back-translation + 0.40×judge; threshold 0.75; term failure hard-caps below threshold.
- Partial verse: ≥40% substring → full verse + info flag; <40% → null + review; tunable in Phase 2c.
- Quran misquote: insert correct translation + block flag (matches frontend examples.js behavior).
- Diacritized verses (D-044, D-045, Phase QT): all 6236 verses; the quoted words with Tanzil's own marks come back as the info flag `quran_diacritized` (`{verse}`, `{ref}`); `segment.source` stays as typed and §4 is unchanged; ambiguous / not found / span inside a word / unaligned verse / missing file → no diacritized text.
- LLM call policy (D-011): 1 retry with backoff per provider, failover primary → fallback with `provider_fallback` info flag, fail safe to `data=None` (caller emits `output: null` + review); temperature 0.2, seed 7.
- Cost accounting (D-012, price list and prefix rule superseded by D-031): `app/llm/pricing.py`; prices verified 2026-10-03 with source URLs in the file.
- Eval metrics (D-015): unit = case × target; term accuracy, scripture integrity (ref cited + `null` or approved verse text), referral recall/precision/over-referral (referred = segment `level D` or `fatwa_like`), errors per 100 (quran/hadith/term/referral; ruling = human). Mean + sample sd. Ids mapped `gt↔mt`, `raw↔llm`, `mowatten↔mowatin`.
- API hardening (D-016): CORS exact allowlist + `*.mowatin.pages.dev` previews; per-IP limit on `/v1/*` with `TRUSTED_PROXY_HOPS`; body/text cap 413; `nosniff`/`no-referrer`/`no-store`; docs off in production; no user text in any log; FastAPI 0.142.2 + Starlette 1.7.0; render.yaml without `rootDir`.
- Phase 2d pipeline (D-017): review rule = `needsReview()` in api.js (`report.py`); §4 disclosure string; flag text from `flags.ar.json` by key; hadith exact match, fabricated first, every quote checked; fatwa = warn `fatwa_referral` + separate info flag with `referral.json` `message.ar` once filled; LLM paths `output: null` + confidence 0 → review until Phase 3; compare = empty baseline; raw = no handling.
- Level-D output (D-022, Phase R referral, approved by the user taking over from Mohammed): a `fatwa_like` segment's `output` = literal translation of the question (`raw_v1` prompt, checked by `verify()` on the question alone so an added ruling is judged as an added claim) + blank line + `referral.json` `message.<lang>` + one `- name (country): url` line per `bodies.<lang>`. No translation (no LLM, failed call) keeps `output: null`. The warn `fatwa_referral` flag keeps it in review. Contract shape unchanged; supersedes the D-017 "fatwa question returns null until Phase 3" line.
- Sourced hadith (D-023): when every «…» quote matches `hadith.json`, the segment is localized (term lock) and verified, keeping source + grade + info `hadith_sourced`. Any unsourced/fabricated quote: no LLM call, `output: null`, review.
- Segmentation (D-024): sentences at `. ؟ ! \n`; a sentence with a fatwa signal (`classifier.is_fatwa_like`) stays one segment; other sentences split at `، ؛` as before.
- Missing check = 0 (D-021): a verifier check that cannot run (`JUDGE_*` unset, call failed, no data) scores 0, never 1. Without a judge, confidence is at most 0.60, so every LLM segment goes to review. Back-translation = Dice over normalized character trigrams (stdlib). Avoid words match whole words only. Cache TTL 1 h on top of LRU 1,000.
- Workshop alignment (D-025..D-027): localizer uses `localize_v2.txt` (explicit no-addition / no-scripture-from-memory / exact-terms / JSON-only rules; v1 unchanged). `openai_compat` provider with `<SLOT>_BASE_URL` (https anywhere, http + empty key only for localhost/127.0.0.1; unknown price = $0 + `price_unknown`). Lexical retrieval over `data/**` + constrained prompts instead of fine-tuning or a vector DB.
- Phase SEC (D-034..D-039): per request ≤ `MAX_SEGMENTS` (6) segments, the rest one null segment in review; ≤ `LLM_CALL_BUDGET` (28) routed calls incl. the judge; no new call after `REQUEST_DEADLINE_S` (90); ≤ `LLM_DAILY_CALL_BUDGET` (1000) per UTC day per process; refused call = `output: null` + warn `limit_reached`; `limit_hit` log. Quran near match bounded (8+ chars, shared words, length, top 20, 400k cells). Fatwa/attribution matching on `canonicalize_for_matching()` (Cf, marks, tatweel, alef/ya; ta marbuta kept); unbracketed attribution → Quran/hadith handler → null + review, no LLM. Prompts `localize_v3`, `raw_v3`, `backtranslate_v2`, `judge_v2` + `neutralize_tags()` + post-check (`injection_suspected`). `mode=raw` confidence 0 + warn `raw_unprotected`. Cache: only non-degraded responses, 64 MB cap.
- Contract alignment (D-014): backend translate request/response now match ARCHITECTURE.md §4 exactly (`target_lang`, §4 audiences, `segments[]` with `type/level/locked_terms/marks/flags{severity,text}/baseline`, `summary`, `review_queue: int[]`). No `meta`: cost per request (Phase 3c) must be logged, or added to §4 with approval.
